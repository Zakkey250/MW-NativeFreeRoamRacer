LimitBreaker 0.1.2-skin-capacity.1 — eight-car body transparency

Base: accepted 0.1.1-render-fix.1, NFSMWLimitBreaker-restart-exp10-audio.
Do not substitute the withdrawn experimental.35 project in NFSMWLimitBreaker.

Reproduced cause
VehicleRenderConn::Load (EN1.3 0x75D220) assigns normal writable composite
slots 1..4. In an eight-car field the remaining cars received slot 0, an empty
body composite hash, and uninitialized wheel/spinner hashes. Their body texture
replacement resolved to DEFAULTALPHA. The body meshes still existed.
The CarLoader arena and relevant slot pools were not exhausted in this repro.
This path is shared by native MW and imported Carbon race introductions.

Correction
- Preserve native slots 1..12, including precomposite slots 5..12.
- Add normal writable slots 13..20, with native release/free-bit handling.
- Mark only these new slots as composited skins in RideInfo.
- Generate 24 local destination textures (skin/wheel/spinner), cloning the
  installation's original writable templates and assigning distinct virtual
  image ranges. Original compressed textures are preserved byte-for-byte.
- GlobalMemoryFile.bin contains a cached CARS/TEXTURES.BIN header. Updating
  only the latter leaves old streaming offsets active. Remove only that cache
  record so the game reads the current header from disk. Other records/data
  remain intact. This is not the editor world cache.
- Require SHA-256 matches for BOTH prepared files before enabling skin hooks.
  Missing/mismatching resources leave the native skin path unmodified.
- No CarLoader arena expansion, audio expansion, model restriction, or forced
  shared tuning is introduced. Paint/vinyl resources remain independent.

Preparation (read-only source, output outside the game)
  python tools/Prepare-SkinCapacity.py --game GAME_DIRECTORY --output NEW_DELTA
Uses the local World2MW/CourseEditor/PublicWeb/local TPK reader and Pillow.
It rejects already-expanded files, malformed entries, and stale source cache
headers. Review manifest.json. The output is installation-specific; NEVER
copy the lab's CARS/GLOBAL files onto Main or another modded installation.
Prepare separately from each destination's current files.

OFF. OFF returns before formatting/file writes and stops the diagnostic
polling thread after functional initialization. It also omits the exception
capture handler. Existing production logs/settings are not removed.
The existing ResourceLimitsV1 export is retained. No new third-party loader
diagnostic ABI has been invented.
