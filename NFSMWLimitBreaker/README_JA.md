# NFSMW Limit Breaker

NFSMW Limit Breaker v0.1.1 Hotfix は、Need for Speed: Most Wanted (2005) の車両上限を安全に20台から最大32台へ拡張する独立ASIです。10本の `PVehicle*` テーブル、AIターゲット用 `ISimable*` リスト、車両ごとの音声・物理・コンポーネント登録リストを64枠の別領域へ移し、関連する車両・交通量上限を一括して変更します。

0.1.1では車両描画接続リストも拡張し、20枠のまま残っていた領域の容量超過を修正しました。[Hotfixの変更点](RELEASE_NOTES_v0.1.1.md)を参照してください。

## 互換性と安全設計

- 6,029,312バイトのNFSPatcher英語版1.3 EXE（通常版および4 GB/LAA化版）が対象です。
- EXE全体のSHA-256と全パッチ箇所の元命令を確認してから変更します。
- Unlimiter、Extra Options、Native Free Roam Racers、MW Advanced Civilian Vehiclesへのパッチや依存はありません。
- 15本のリストそれぞれに64ポインタ分のプロセス寿命領域を確保します。リリース上限32台に対して32枠の上書き抑止余裕を残します。64台対応を意味するものではありません。
- 対象リストがすべて既知の型で、かつ空の時だけ一括して有効化します。競合や読み込み遅延があれば何も変更せず無効化します。
- 移動後の各リストの型、データポインタ、容量、件数、カナリア、旧インライン領域を監視し、`scripts/NFSMWLimitBreaker.log` に記録します。

対応SHA-256:

- NFSPatcher英語版1.3: `80774C2E5D619B4F120B48D4462896FD504C263399D203A238769CFFDE1D253C`
- LAAフラグとPEチェックサムだけが異なる版: `B248271BF8EAC8C9B283B8C95E3ADD672B713BF529B05F1780E58268493B9D06`

## v0.1.1 Hotfix

リリース版は実プレイで安定を確認した論理32台／物理64枠の車両機能と、任意・再起動必須・能力API交渉式の8 MiB音声領域拡張を収録します。INIで選べる車両上限は `20 / 24 / 28 / 32` のみで、配布推奨値は32です。CarLoader拡張コードと設定項目は収録しません。

`LBEngineAudioExpansion = 1` はゲーム所有の音声ミキサ領域を起動前に8 MiBへ拡張します。対応MODは `NFSMWLB_QueryResourceLimitsV1` のABI・能力ビット・実容量を確認した場合だけ追加音声枠を利用できます。機能が無効または利用不能でも車両上限機能は継続します。

## 開発履歴

`0.1.0-experimental.3` は、二度の実プレイCTDから確認された14本の固定長リストを一つのトランザクションとして移設します。前版で未移設だった `PVehicle*` テーブル要素の一つは後続要素を破壊しており、車両音声・物理系の2本は22件、車両コンポーネント登録リストは21件まで達していました。最後のリストは隣接レジストリを上書きし、破棄処理の `0x0041C17B` でCTDを起こしました。本版はこれらとAIターゲットリストを同時に移設し、確認済みの5か所の上限計算を更新します。

`0.1.0-experimental.4` は同じ移設処理に診断機能を追加した版です。14本が無傷のまま24件へ達した直後に発生した第三のCTDについて、残存する20枠固定ベクタを24件到達時に列挙し、アクセス違反時には `scripts/NFSMWLimitBreaker-crash-<PID>-<番号>.dmp` を保存します。例外を抑止・回復する機能ではありません。

`0.1.0-experimental.6` は experimental.5 のスタック上の被害車両候補ベクタ修正を維持しつつ、クラッシュ診断をゲーム本体内の例外だけへ限定します。他ASI内で処理されるfirst-chanceアクセス違反は無視し、対象ダンプも1起動につき最大1本です。これにより、診断ダンプの連続書き込みによる走行中の引っ掛かりを防ぎながら、Limit Breakerに関係するゲーム本体側の異常は引き続き採取できます。ゲーム本体の元vtableや他MODは変更しません。

`0.1.0-experimental.7` は、24台時の追跡中に最後に発生したCTDを修正します。AI車両マネージャの `+0xC4` には別の20ポインタ固定ベクタが埋め込まれており、21・22件目が `+0x124/+0x128` の追跡要求フィールドを上書きし、最終的に `0x0043EAFB` のNULL読み取りへ至っていました。本版はマネージャ生成命令のvtable即値 `0x0043CA61` だけを専用の可変vtableへ置換し、上限32ポインタの固定再利用プールで保持します。また、元が固定インライン型だった被害車両候補ベクタには通常終了時の破棄呼び出しが生成されていないことが実測カウンタで判明したため、毎回のヒープ確保から上限付き再利用プールへ変更しました。他MODは変更しません。

`0.1.0-experimental.8` は、experimental.7で24台の最終追跡完走が確認できたことを受け、論理上限を28台へ段階的に拡張します。物理容量32は変更せず4枠の抑止余裕を残します。24台到達時と設定上限到達時に主PVehicleポインタの可読性と残存20枠固定ベクタを別々に記録し、ゲーム本体側のアクセス違反採取も24台から有効にします。AI車両マネージャのグローバルがライフサイクル遷移中に別の空オブジェクトを指す場合は異常と誤判定しません。

`0.1.0-experimental.9` は任意利用の `NFSMWLB_ReservePopulationV1` 能力APIを追加します。利用側MODはロード済みASIから固定名のexportと能力ビットを検出するため、Limit Breakerのバージョン番号、内部アドレス、ロード順への依存はありません。2秒で失効する予約はネイティブ交通生成を一時的に絞るだけで、論理上限を緩和したり車両を削除したりしません。NFRR alpha.69との実プレイでは28台到達、予約165区間、5回の開始・終了、追跡中を含む継続生成、異常0を確認しました。

`0.1.0-experimental.10` は、その受け入れ試験で追跡中の生存台数が長時間 `28/28` に張り付き、アザーカーの補充余地が不足した結果を受け、論理上限を32台へ進めます。14本の固定ベクタ、被害車両候補、AI車両マネージャの物理容量は64枠へ先行拡張します。現在の32台では32枠の上書き抑止余裕を維持します。予約APIの名前・ABI・能力ビット・リース動作は変更しません。CarLoader拡張を使用しない条件で32/64構成の実プレイ安定性を確認済みです。36・40・44・48台は配布用の安全範囲に含めません。

`0.1.0-experimental.10-audio.1` は、実プレイで安定を確認した experimental.10 の32/64車両実装を変更せず、任意の `LBEngineAudioExpansion` だけを同じASI内の独立機能として追加します。既定値はOFFです。ONで起動した場合だけ、ゲーム所有の音声ミキサ領域を起動前に8 MiBへ拡張し、実領域とアロケータ記述子の一致を確認できたときだけ `NFSMWLB_QueryResourceLimitsV1` へ能力を公開します。この機能だけが失敗しても車両上限機能は継続します。音声枠数そのものは変更せず、対応MOD側が能力APIを確認して別途選択します。設定変更にはゲームの完全再起動が必要です。

`0.1.0-experimental.10-audio.2` は機能と8 MiB容量を変えず、追加音声診断だけを最適化します。音声領域の整合性確認を100 msごとから2秒ごとへ間引き、アロケータ残量ログも64 KiBではなく256 KiBの変化単位へ集約します。experimental.10由来の車両監視周期、32/64車両処理、能力API、音声割り当て動作は変更しません。

`0.1.0-experimental.10-audio.2-carloader.1` はCarLoader領域拡張を調査した不採用版です。256 MiBを有効にした実走では約1秒規模のカクツキが発生し、同じASIのままCarLoaderだけを無効化したA/B試験で安定へ戻りました。この機能はv0.1.1 Hotfixからコード・設定とも削除しています。

物理、警察、描画、ストリーミング、音声、第三者MODの生成処理がすべて20台超に対応するとはまだ主張しません。特にフリーロームのエンジン音声プールには別の上限があります。

通常のゲーム処理は、論理上限に達する前に車両を整理または生成延期します。任意の第三者MODによる上限超過生成を安全に拒否できる汎用フックは未実証のため、INIは32を超える値を意図的に拒否します。

## 導入

`NFSMWLimitBreaker.asi` と `NFSMWLimitBreaker.ini` をゲームの `scripts` フォルダへコピーしてください。配布用の安定基準は論理32台／物理64枠、`MaxVehicles = 32` です。音声領域の独立機能を利用する場合だけ `[Audio] LBEngineAudioExpansion = 1` にして完全再起動してください。NFRRは能力APIを確認し、条件を満たさない場合は従来の音声枠へ安全にフォールバックします。

静的検証や起動確認は、ゲームプレイ受け入れ試験の代わりにはなりません。破棄処理、セーフハウス遷移、レース、追跡、逮捕、フロントエンド復帰を確認してから、ゲームプレイ上安全と判断してください。
